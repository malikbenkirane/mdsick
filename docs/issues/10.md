# fix mermaid deadlock on failed render

## Problem

When a mermaid block fails to compile (`mmdc` reports an invalid diagram, or
any error along the `Compile` path occurs), the process deadlocks. The
collector goroutine in `internal/transformers/mermaid.go` waits for
`done == count`, but error events (`err != nil`) are logged and `continue`d
without incrementing `done`, so the collector never sees the completion
condition. It blocks on `<-m.event` (mermaid.go:106) forever, because
`close(m.event)` only runs after `Transform` returns — and `Transform` cannot
return until `wg.Wait()` (mermaid.go:159) collects that very goroutine.
Result: `fatal error: all goroutines are asleep - deadlock!`, exit 2.

This is lethal in batch mode: one invalid diagram in one file crashes the
whole run.

Verified experimentally; also documented in AGENTS.md.

## Fix strategy

- Track errors separately in the collector. The completion condition becomes
  `done + errorCount == count`; error events increment `errorCount` instead
  of being skipped silently.
- The progress bar counts successful diagrams only; its final description
  reports failures: `mermaiding done (N errors)`.

## Failure artifact (invalid diagram)

A failed diagram does **not** kill the render and stays silent on stderr:

- The original fenced `mermaid` block survives in the rendered HTML.
- Every line of that fence is prefixed with its diagram-relative line number
  (`1| lang mermaid`-style), because `mmdc` error messages reference those
  line numbers and the author must be able to locate them.
- Directly after the failed block, a new fenced block with language `text`
  contains the **full** captured `mmdc` stderr+stdout. No truncation.

## Environment gate (missing `mmdc`)

- Upon encountering the first mermaid block, before the walk proceeds,
  check that `mmdc` is available on PATH.
- If it is missing, abort the **whole run** in both modes (stdin and batch):
  print one explicit message, exit nonzero, open nothing in the browser.

## Verification

One end-to-end regression test: a document containing one valid and one
invalid mermaid block must render to completion — no deadlock, complete
HTML, and the error artifact present. Run at the sub-process level so the
observable boundary (process finishes) is what is asserted.
