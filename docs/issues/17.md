# 17. `mdsick-reflow`: un-wrap markdown prose for pasting into GitHub

GitHub comment boxes (issues, PRs, reviews) render a single newline as a
hard break. A markdown file written against an 80-column terminal is
therefore full of wrap artifacts: every soft newline the author used for
wrapping becomes a visible break on GitHub. `mdsick-reflow` joins those
wrap lines back, so `cat doc.md | mdsick-reflow | pbcopy` produces text
that pastes to GitHub as if it had never been wrapped.

## Scope

- Stdin only, no args, no flags. Refuses (errors) when stdin is a TTY,
  mirroring `mdsick`'s piped mode. Output goes to stdout with a trailing
  newline preserved from the input.

## Approach: miner, not re-serializer

Parse with a plain `goldmark.New()` plus only the table extension
(`extension.Table`). No renderer runs; the AST is used to decide where to
join, and the output is the original source with some newlines replaced.

- Walk the AST to identify prose blocks. A prose block is:
  - a `Paragraph`, or a `Paragraph`/`TextBlock` reachable under
    `Blockquote` (see below);
  - list items are **not** prose for this purpose and are untouched;
- Every other block type is frame or immune content and is left
  byte-identical: `Heading`, `ThematicBreak`, `FencedCodeBlock`,
  `CodeBlock` (indented), `HTMLBlock`, `Table`, `List`.
- For each prose block, take its `Lines()` source segments and join the
  newline between two consecutive segments with a single space,
  **except** when the second line begins a hard break
  (`ast.HardLineBreak` found via the block's inline children) — hard
  breaks are honored and re-emitted below.
- Seam rule: trim leading/trailing whitespace of each joined segment,
  join with exactly one space (`"word word"`). The last line of the
  block keeps its original trailing whitespace and the block keeps its
  blank-line separation.
- Hard breaks are re-emitted as a trailing backslash (`\`), a form that
  survives pbcopy round-trips and editors configured to trim trailing
  whitespace on save.
- Wrapped inline constructs need no special handling: the miner joins at
  the soft break regardless of what inline node spans the seam, so
  `*emphasis\nwrap*`, `**bold\nwrap**`, `[anchor\nwrap](link)` and
  `` `code\nspan` `` all refill naturally. Caveat: a seam only joins if
  it is a soft break — trailing two spaces on a wrap line turns it into
  a hard break and it stays a break.

## Blockquote

Inner prose of a `Blockquote` refills. Per line, strip the leading
`>` markers (count the marker run, then following space), join the
de-marker'd segments by the seam rule, and re-emit one marker run plus
the joined text. Blank lines inside the quote separate quote paragraphs
and survive. Lazy continuation lines (a paragraph line under a blockquote
not starting with `>`) are part of the blockquote's paragraph and refill
with it.

## Tables (explicit non-goal)

GFM table rows are atomic: a newline ends a row, so a row wrapped at
80 columns already renders as a broken table on GitHub, and joining
between rows would delete a row from the output. The table extension is
enabled **only** so the joiner recognizes tables as immune. Long cell
text is not fixable by reflow; fix the sentence instead.

## Packaging

- Thin binary: `cmd/mdsick-reflow` reads stdin, calls the package, prints
  the result.
- Logic: `internal/reflow` exposes the transform, e.g.
  `reflow.Reflow(source []byte) ([]byte, error)`.

## Tests

Table-driven in `internal/reflow`, one case per rule:

- paragraph join across a soft break (seam = one space, trimmed);
- wrapped inline constructs: emphasis, bold, link, code span;
- hard break honored and re-emitted as `\`;
- blockquote refill with regenerated `>` markers;
- lazy continuation refills with the quote;
- survivors left untouched: fenced code, indented code, heading,
  thematic break, list, HTML block, table (with the table extension on);
- multiple blocks separated by blank lines.
