# prose issue-reference detection with a small language model

## Idea

Today (see issue 9) prose linkification of issue references uses fixed
lexical patterns: `issue NN`, full/tilde paths (`docs/issues/43.md`,
`` `39.md` ``), and `#NN`. These rules cover the current corpus, but natural
language is open-ended: references can be phrased as `fixes issue number
twenty-two later this sprint`, `see the epic around 25`, or
`points to docs/issues/5 and its follow-up`. Regexes either miss these
or over-match.

## Proposal

Evaluate whether a small language model (SLM, a few hundred million to a
few billion parameters, runnable locally on a laptop) can detect prose
spans that reference issues generically, from a small labeled sample of
issue files. Runners to consider as of late 2026: llama.cpp bindings,
Apple silicon-friendly runtimes, or a hosted Hugging Face inference
endpoint. Forms worth comparing:

- Regex-free NER-style tagging: a fine-tuned token-classification model
  (e.g. a small BERT/RoBERTa variant) emitting reference spans.
- Few-shot prompting of a small instruct model (0.5–3B) to extract
  candidate spans as JSON, normalized to `{ref, source, offset}`.
- Hybrid: LLM proposes candidates, existing resolvers (numeric lookup)
  confirm/mute them.

## Illustrative false positive risk

A 2025-style corpus of this repo shows prose like `PR document for issue
10 plan deviated from the original` — a model must label only `issue
10`, not the whole phrase, and must skip mentions inside quoted titles
or historical narrative where linking is questionable.

## Success criteria

- ≥95% span-level precision at fixed recall on a hand-labeled sample of
  50 issue files (label set to be produced).
- Latency acceptable for a batch render of hundreds of files (target:
  <1 s per file on a modern laptop, CPU or small-GPU).
- The rewrite pipeline gains a pluggable resolver interface: existing
  lexical resolvers remain the default; the SLM detector is opt-in.

## Open questions

1. Ground truth: hand-label 50 files or synthesize injections?
2. Which runner: native macOS (Metal) vs. CPU-only portable?
3. Cost/value: ~70 hash refs and ~40 `issue NN` prose refs today — the
   labeled tail seems small. Reassess the value once the corpus grows;
   avoid running a model where three regexes suffice.
4. How does the exclusion of fenced code blocks and the inclusion of
   code spans translate from the current corpus to the model's usage?

## References to explore

- Hugging Face token-classification models suitable for reference
  extraction.
- Cross-encoder or small reasoning-by-number pairs: issue numbers
  assume ordinal meanings (epic vs. sub-issue) that a model might use
  as a signal — that's semantically dangerous, but interesting to
  evaluate as the numeric resolver's fallback.
