# specialized mdsick-issues command

## Use case

`mdsick` so far has one function: render markdown to GitHub-styled HTML,
either from stdin or, with a terminal on stdin, by batch-rendering every
`*.md` in the current directory. That single-purpose design follows the
Unix philosophy, and it should stay.

But a frequent use case has emerged across all the repositories where
this workflow has been adopted: issues are tracked as plain text files
in `<parent>/<dir>` trees such as `docs/issues/` and `docs/issues/closed`,
so every developer can see every issue with merely a repo pull — without
requiring a third-party platform. Glancing at Open and Closed issues
today means running two shell commands in two directories and getting
two separate browser windows, each a flat directory render:

```sh
sh -c "cd docs/issues/closed && mdsick $@ Closed Issues" &
sh -c "cd docs/issues && mdsick $@ Open Issues"
```

## Proposal

Add a specialized `cmd/mdsick-issues` that serves this need in one page.
It reuses what `cmd/mdsick` already knows how to do (temp workspace,
batch rendering, index generation) but targets `docs/issues` and
`docs/issues/closed` and builds a single page with two sections:
**Open Issues** and **Closed Issues**.

## Repo discovery

The tool walks up from the cwd until it finds a `.git` or `.jj`
directory to locate the repo root; failing that, it errors explicitly.
`docs/issues/` and `docs/issues/closed/` must exist directly in the
repo root; an explicit error otherwise. There is no discovery below the
root. By contract the command is run from the repo root.

## Page shape

- One landing page with two fixed sections: **Open Issues** and
  **Closed Issues**.
- A dedicated `writeIssuesIndex` template (sections, issue entries,
  warnings block); the existing `writeIndex` is not stretched to serve it.
- Positional args set the single page title; the section headers are
  fixed.
- Default title: the repo root's last two path components plus
  ` Issues` (`path/to/repo` → `to/repo Issues`).

## Identity & layout decisions

All generated issue pages are **flat** in the temp workspace, no
`closed-` prefix: the issue number is the sole identity of a page
(`NN.md` → `NN.html`), regardless of open/closed state. Rationale: issues
move between `docs/issues/` and `docs/issues/closed/` over time, and a
reference like `#33` must resolve to *the* issue 33 no matter which side
it currently lives on; a directory path found in a reference (e.g.
`closed/8.md`) is not trustworthy and is ignored — numbers alone resolve.

**Fail hard** (explicit error, refuse to run) on **duplicate issue
numbers**: the same `NN` existing both as `docs/issues/NN.md` and
`docs/issues/closed/NN.md` would make the flat `NN.html` ambiguous.

## Link rewriting

Every reference tier is rewritten in the temp copies so a reader can
navigate from the index and from any issue page:

| Style | Example | Notes |
|---|---|---|
| `#NN` | `#21`, `#23`, `#25` — most common inline style (~70 uses) | Rewritten to the issue's HTML page wherever it currently lives |
| Markdown link `[NN](NN.md)` | `[30](30.md)`, `[22](22.md)`, also `[8](closed/8.md)` | Rewritten by number; the directory part of the link is ignored |
| Link labeled `epic` | `[epic](22.md)` | Same numeric resolution |
| "issue NN" prose | `issue 9`, `(issue 8)`, `(issue 19)` — ~40 uses | Linkified |
| Full/tilde path prose | `docs/issues/43.md`, `` `39.md` ``, `(`30.md`–`36.md`)` | Linkified |
| Full path label link | `[docs/issues/6.md](6.md)`, `[docs/issues/4.md](4.md)` | Rewritten by number |
| Non-standard | `#10`, `#3`, `#2` (closed issues referenced by hash) | Same numeric resolution |

Boundaries: rewriting skips **fenced code blocks**; **code spans are
rewritten**, since they carry real references (`` `30.md`–``36.md``,
`` `docs/issues/43.md` ``) and no false-positive code-span styles
(`` `issue NN` ``, `` `#NN` ``) exist in the corpus.

Unresolvable references (typo, `NN` absent from both sides) are **not**
dropped: they collect into a **warnings section at the bottom of the
index page** — broken references are raised there to be fixed/reported
later by a developer, not buried in stderr.

## Code sharing

`cmd/mdsick` and `cmd/mdsick-issues` share internals: an
`internal/workspace` package (`tempWorkspace`, `copyStyle`) and an
`internal/markdown` package (`newMarkdown`) are extracted and imported
by both binaries, rather than duplicating the plumbing.

## Scope guard

`cmd/mdsick-issues` hardcodes the `docs/issues` + `docs/issues/closed`
layout. It must be additive: `cmd/mdsick` keeps its single-function
behavior intact.
