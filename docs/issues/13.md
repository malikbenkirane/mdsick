# harden issue 10's assertions: cover what tests cannot yet assert

Follow-up to [10](10.md) (mermaid deadlock fix). The fix is implemented and
tested, but `mermaidfail_test.go` and `root_test.go` leave a few behaviors
unasserted. Close the gaps.

## Gaps

### Gate placement relative to the walk

The spec required: "upon encountering the first mermaid block, before the
walk proceeds, check that `mmdc` is available on PATH." The current tests
only assert missing/present behavior at the function level
(`checkMmdc` / `checkMmdcBatch`); nothing asserts the order of operations in
`run()` / `runDir()` — e.g. that gate failure happens *before* any
workspace is created, files are rendered, or the browser is opened.

Add a subprocess-level test: document containing mermaid, `PATH` stripped of
`mmdc`; assert the process exits nonzero, prints the single gate message,
and opens nothing (no temp dir path printed to stderr, no `open` invocation
— use a fake `open` on PATH that records its args to a scratch file; on
other platforms this test must be skipped or shimmed accordingly).

### Tilde-fenced mermaid blocks

`hasMermaid` matches only ```` ```mermaid ```` strings
(`cmd/mdsick/root.go:242`). A `~~~mermaid` fenced block does not trip the
stdin-mode gate, yet the transformer will compile it: with `mmdc` missing
that ends up as an infra error and nonzero exit, which reaches the same
outcome by accident rather than by the specified gate.

Decide deliberately:

- either broaden the detection (and the gate) to tilde fences,
- or document that tilde fences are not gated (and verify the eventual
  infra-error abort is still a clean nonzero exit with one message, not a
  crash),

and assert the chosen behavior in a test. Note the existing unit-style
test `tilde fence does not count` in `root_test.go` encodes the current
behavior; change it if the decision changes.

### Batch-mode gate message

The spec says "print one explicit message, exit nonzero". For stdin mode the
exact message is exercised; for batch mode (`checkMmdcBatch`) nothing
asserts either the message or that the whole run aborts without rendering
any file or opening the browser. Add a subprocess-level batch-mode test:
directory with markdown containing mermaid, `PATH` without `mmdc`, assert
nonzero exit, exactly the gate message on stderr, and no rendered output
written.

## Non-goals

- Visual/browser verification remains out of scope (unassertable by
  automated tests; still a manual check).
- Do not touch the warts parked in [11](11.md).
