# relax issue discovery: ignore files that are not NN.md

## Idea

`mdsick-issues` exits with 1 when `docs/issues` or `docs/issues/closed`
contains a `.md` file whose base is not a bare number:

```
Error: issues: unexpected issue filename "28-original-grill-me.md" in open (want NN.md)
```

The strict rule (`internal/issues/list.go`, `listNames`) turns any
descriptively named note dropped into `docs/issues` into a hard failure
of the whole tree scan, and the failure buys nothing: files that are not
`NN.md` carry no issue number, so the tooling has nothing to index for
them anyway. The rule is safe to replace with a skip.

## Proposal

In `listNames`, replace the error return for non-numeric `.md` files
with a silent skip (or at most a one-line stderr note), keeping the
existing `continue` for directories and non-`.md` entries unchanged.
Only `NN.md` files become `Row`s; everything else is invisible to the
listing, dedup (`duplicate issue number`), and downstream rendering.

Cases covered by the skip, all currently fatal:

- `28-original-grill-me.md` — numbered descriptive filename.
- Wip drafts like `notes.md`, `scratch-idea-3.md`.
- Files from other tooling that coexist in the directory.

The same skip applies to both the `open` and `closed` sides, so
`duplicate issue number` detection keeps considering only real
`NN.md` files and cannot be tripped by descriptive names.

## Alternative considered

- Parse a leading `NN-` prefix out of `NN-slug.md` names and index them
  as issue NN. Rejected for now: it creates a second way for two files
  to claim the same number, and it moves the "what is an issue file?"
  question from "digits only" to a documented naming convention that
  every issue's slug must obey. Revisit if the corpus starts routinely
  holding numbered slugs that should be indexed.

## Success criteria

- `mdsick-issues` exits 0 with `28-original-grill-me.md` present in
  `docs/issues`, and the file is not listed as an issue.
- No change in behavior for trees where every `.md` file is `NN.md`.
- Existing tests for `List` still pass; a new test asserts non-numeric
  `.md` files are skipped on both sides.
